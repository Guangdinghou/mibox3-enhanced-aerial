# 小米盒子 3 增强版 Aerial 改造项目设计

## 目标

建立一个可独立上传 GitHub 的中文项目，复刻小米盒子 3 增强版（MDZ-18-AA、MiBOX3_PRO、Android 5.1）从备份、ROOT、清理到 Aerial 桌面接管及恢复的完整流程。

## 非目标

- 不声称支持其他型号、固件或分区布局。
- 不提交 APK、提权程序、分区镜像、ADB 密钥、设备编号、IP、账号或其他私人数据。
- 不绕过来源校验，不在检查失败后继续写入。
- 不把真实遥控、视频播放及开机画面等人工验收伪装成自动验证。

## 约束

- 目标设备必须同时匹配 `MiBOX3_PRO`、Android 5.1/SDK 22 与预期 MediaTek 平台特征。
- 每个危险阶段单独执行、单独确认、单独恢复；默认只检测，不自动串行完成全部改造。
- 修改前必须生成带哈希的备份和状态快照。
- 下载第三方文件时固定版本、来源和 SHA-256；校验失败立即停止。
- 所有停用操作使用用户级可逆状态；用户级卸载必须先备份 APK，并提供逐包恢复。
- 永久 ROOT 写入前必须确认临时 ROOT、分区名称、挂载状态、空闲空间和备份完整性。

## 采用方案

选择独立的设备专用仓库，而不是向 `cleanyourtv` 添加高风险功能。仓库提供分阶段 Shell 脚本、共享安全检查库、状态清单、恢复脚本、中文文档和离线测试。第三方二进制由使用者从固定公开来源下载并校验，不进入 Git。

曾考虑两种替代方案：一是在 `cleanyourtv` 内只发布安全版，但无法复刻 ROOT 与卸载过程；二是只写操作笔记，但缺少前置检查、可重复执行能力和恢复保障。两者均不符合本项目目标。

## 流程设计

1. `doctor` 只读识别设备、系统、芯片、连接方式、调试状态和磁盘空间。
2. `backup` 保存包列表、停用列表、属性、设置、分区表、启动脚本及关键分区镜像，并生成哈希清单。
3. `fetch` 获取固定版本的 Aerial、临时 ROOT 与 SuperSU 资源，逐项校验。
4. `temp-root` 仅运行最小身份检查，随后清理临时文件并确认 SELinux 状态。
5. `permanent-root` 在全部门禁通过后安装 system-mode SuperSU，保留原厂恢复/TEE 启动逻辑，并生成撤销入口。
6. `debloat` 按白名单和清单逐包操作，保留影视仓、电视管家、云视听小电视、乐播、米家及高清播放器。
7. `launcher` 安装 Aerial、配置应用顺序和屏保、验证 HOME 声明，最后才可逆停用小米桌面。
8. `verify` 在每次重启后核对 ROOT、SELinux、停用状态、Aerial、HOME 与保留应用；输出人工验收清单。
9. `restore` 支持按阶段逆序恢复，也提供完整恢复说明，不承诺跨固件恢复分区镜像。
10. 仓库根目录提供 macOS/Linux 中文菜单入口及 Windows PowerShell/批处理入口；普通用户可双击启动，但危险阶段仍逐项确认。

## 公开与隐私

仓库只保存模板化日志示例。运行生成的 `backup/`、`work/`、`shots/`、下载文件和密钥全部忽略。诊断报告自动遮蔽设备序列号、网络名称、地址和账户信息。

## 验收标准

- 所有脚本支持 `--help`，危险脚本默认拒绝不匹配设备。
- 离线测试覆盖型号拒绝、哈希失败、缺失备份、重复执行、逐包恢复和敏感信息扫描。
- 新用户能仅按 README 完成只读检查与备份；高风险阶段必须明确阅读风险并输入确认语句。
- 每项实际修改都有对应恢复命令和验证命令。
